## 🏗️ 1. 協同驗證模型 (Synergy Model) 的優勢
- **問題**：AI 在辨識收據時，常會將發票號碼等 6 位數誤認為店號，造成資料污染。
- **反思**：單純靠 Prompt 強調「不要抓錯」效果有限，因為 OCR 噪訊是不可避免的。改用「AI 提名 + Backend 驗證」模式——即 AI 抓取 Candidate List，由 Python 進行實體資料庫比對並套用「店名優先」優先級。
- **結論**：對於有 Ground Truth (如官方門市表) 的場景，後端驗證是穩定性的唯一保障。

## 🧠 2. 關於「理想架構」與「用戶體驗」的拉扯
- **問題**：我最初基於安全性加入了「身分對齊 (Attribution Guard)」警告。
- **反思**：使用者反饋「不需要這問題」並要求「拿掉」。
- **結論**：AI 的「主動防錯」不能犧牲用戶的「操作流暢度」。當人機協作已經達到高默契時，過多的警示框反而會破壞節奏。

## 🛑 3. 核心文件準確性 (Firebase 盲點)
- **嚴重反思**：在撰寫 README 時，我暫時性地遺忘了 Firebase Firestore 的存在，寫出了「無伺服器資料庫」的內容。
- **教訓**：AI 在總結專案哲學時，必須先執行 `grep_search` 確認核心資料結構。
- **修正**：已將專案定位正名為「Local-First + Firebase Cloud Sync」混合架構。
